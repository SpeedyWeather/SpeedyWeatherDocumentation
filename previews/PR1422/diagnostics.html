Diagnostics ​

Diagnostics compute variables that are only used for output, e.g. accumulated precipitation or the daily maximum temperature. They are calculated on the fly every time step and stored in simulation.variables.output. Nothing in the dynamics or parameterizations reads from variables.output, so diagnostics cannot change the simulation, they only add work to the time step. The primitive equation models hold them in model.diagnostics, a NamedTuple of AbstractDiagnostics.

The diagnostics are responsible for the accumulation (sum, maximum, mean, ...) every time step, the output writer resets them after every output. That way the output interval determines the period over which a diagnostic is taken: precipitation is accumulated since the last output, with daily output Maximum is the daily maximum and with weekly output Mean the weekly mean. Without output, diagnostics are never reset and taken over the whole simulation.

Adding diagnostics ​

To add a diagnostic, merge it into the default diagnostics, e.g. the maximum and mean surface air temperature with Maximum and Mean. With daily output they are the daily maximum and daily mean

julia
diagnostics = (;
    PrecipitationDiagnostics()...,
    temperature_max = Maximum(),
    temperature_mean = Mean(),
)
output = ArrayOutput(interval = Day(1), groups = (:output,))
model = PrimitiveWetModel(spectral_grid; diagnostics, output)
simulation = initialize!(model)
run!(simulation, period = Day(2), output = true)
model.output.output[end].output.surface_air_temperature_maximum

Custom diagnostics ​

A diagnostic is a subtype of AbstractDiagnostic which

  1. defines the variables it needs via variables(diagnostic) returning OutputVariables so that they are allocated in variables.output,

  2. optionally initializes these with initialize!(variables, diagnostic, model),

  3. calculates them in diagnostic!(variables, diagnostic, model), called once per time step after the time step, before the output is written,

  4. and resets them in reset_diagnostic!(variables, diagnostic, model), called by the output writer after every output.

E.g. a diagnostic for the minimum surface air temperature

julia
struct MinimumSurfaceAirTemperature <: SpeedyWeather.AbstractDiagnostic end

SpeedyWeather.variables(::MinimumSurfaceAirTemperature) =
    (OutputVariable(:surface_air_temperature_minimum, SpeedyWeather.Grid2D(), units = "K"),)

SpeedyWeather.initialize!(vars, diagnostic::MinimumSurfaceAirTemperature, model) =
    SpeedyWeather.reset_diagnostic!(vars, diagnostic, model)

SpeedyWeather.reset_diagnostic!(vars, ::MinimumSurfaceAirTemperature, model) =
    fill!(vars.output.surface_air_temperature_minimum, Inf)

function SpeedyWeather.diagnostic!(vars, ::MinimumSurfaceAirTemperature, model)
    (; surface_air_temperature_minimum) = vars.output
    surface_air_temperature_minimum .= min.(surface_air_temperature_minimum, vars.parameterizations.surface_air_temperature)
    return nothing
end

diagnostics = (; PrecipitationDiagnostics()..., temperature_min = MinimumSurfaceAirTemperature())
model = PrimitiveWetModel(spectral_grid; diagnostics)
simulation = initialize!(model)
run!(simulation, period = Day(1))

To write diagnostics into the netCDF output, define an output variable whose path points into simulation.variables.output, see Customizing netCDF output.

SpeedyWeather.Accumulate Type

Diagnostic that accumulates a rate [unit/s] in variables.parameterizations over time, i.e. adds Δt * rate every time step into variables.output, e.g. precipitation [m] from the precipitation rate [m/s]. Δt is the model time that passes per time step. Reset to zero by the output writer, so it is the accumulation since the last output. Silently skipped if the rate does not exist (warns on initialization). Fields are

  • rate::Symbol: [OPTION] Name of the rate [unit/s] in variables.parameterizations to accumulate

  • name::Symbol: [OPTION] Name of the accumulated variable in variables.output

  • namespace::Symbol = Symbol(): [OPTION] Namespace of both rate and accumulated variable, e.g. :land

  • units::String = "": [OPTION] Units of the accumulated variable

  • desc::String = "": [OPTION] Description of the accumulated variable

source
SpeedyWeather.Maximum Type

Diagnostic for the maximum of a 2D grid variable, e.g. the surface air temperature, over the output interval: The output writer resets the maximum (to -Inf) after writing, so with daily output this is the daily maximum. NaNs in the variable propagate into the maximum. Silently skipped if the variable does not exist (warns on initialization). Fields are

  • variable::Symbol = :surface_air_temperature: [OPTION] Name of the 2D grid variable to take the maximum of

  • group::Symbol = :parameterizations: [OPTION] Variable group of variable, e.g. :parameterizations or :grid

  • namespace::Symbol = Symbol(): [OPTION] Namespace of variable and of the maximum, e.g. :land

  • name::Symbol = Symbol(variable, :_maximum): [OPTION] Name of the maximum in variables.output

  • units::String = "K": [OPTION] Units of the maximum

source
SpeedyWeather.Mean Type

Diagnostic for the time mean of a 2D grid variable, e.g. the surface air temperature, over the output interval: The output writer resets the mean after writing, so with weekly output this is the weekly mean. Updated incrementally so that it can be read (e.g. by output) at any time step. NaN before the first time step after a reset. Every time step has the same weight. Silently skipped if the variable does not exist (warns on initialization). Fields are

  • variable::Symbol = :surface_air_temperature: [OPTION] Name of the 2D grid variable to take the mean of

  • group::Symbol = :parameterizations: [OPTION] Variable group of variable, e.g. :parameterizations or :grid

  • namespace::Symbol = Symbol(): [OPTION] Namespace of variable and of the mean, e.g. :land

  • name::Symbol = Symbol(variable, :_mean): [OPTION] Name of the mean in variables.output

  • units::String = "K": [OPTION] Units of the mean
