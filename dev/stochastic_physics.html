Stochastic physics ​

Stochastic physics introduces stochasticity into the parameterizations of physical process. There is conceptually several classes of how this can be done

  • Stochastic perturbations of the tendencies

  • Stochastic parameter perturbations

  • Stochastic perturbations to the inputs of parameterizations

all of these use random numbers created from some random processes (white noise or with some autocorrelation in space or time or sampled from some other distribution) and are applied additive or multiplicative.

Separate from this is the StochasticLeapfrog that integrates the complete model as a SDE with a Wiener noise process added to the tendencies.

Random processes ​

The random numbers for stochastic physics come from a random process, a model component model.random_process (nothing by default, i.e. no random numbers are drawn). Once per time step the random process draws a new random pattern after update_random! is called. The stochastic physics then read it from simulation.variables.grid.random_pattern. Currently implemented are

julia
using SpeedyWeather
subtypes(SpeedyWeather.AbstractRandomProcess)
2-element Vector{Any}:
 GridWhiteNoiseProcess
 SpectralAR1Process

All of them have the following options

  • standard_deviation of the pattern at every grid point, by default   so that values beyond () are rare,

  • seed for reproducibility, seed = 0 (default) takes a new random seed at every initialize!,

  • n_patterns the number of independent patterns (default 1),

  • draw_on_cpu = true to draw the random numbers on the CPU also if the model runs on GPU (slower, but the same random numbers on every architecture).

SpectralWhiteNoiseProcess is the AR1 process above with time_scale = 0, so that  : it has no memory, the pattern is drawn anew every time step independent of the previous one (white in time)

With wavenumber = 0 (default) is the same for all degrees , the pattern is then also white in space (spectrally flat). With a wavenumber   it uses the same as the AR1 process above, so that the pattern is white in time but correlated in space. As for the AR1 process, neither the global mean ( ) nor the last degree get noise and the   coefficients are real. There is no clamping by default (clamp = (-Inf, Inf)) to keep the pattern Gaussian, use e.g. clamp = (-1, 1) together with SPPT.

White noise in grid space ​

GridWhiteNoiseProcess draws an independent normal random number with standard deviation at every grid point and every time step. It is drawn directly in grid space, no spectral transform is involved. As grid cells generally differ in area, the pattern is the same at every grid point but not statistically homogeneous on the sphere.

Stochastically perturbed parameterization tendencies (SPPT) ​

SPPT is based on the idea that the dynamics have a higher certainty but that the Parameterizations are more uncertain and hence any stochasticity should scale with the size of the tendencies coming from the parameterizations. Conceptually an atmospheric state is integrated in time as

with the parameterizations being a function of the atmospheric state (column only for the single column parameterizations in SpeedyWeather), time and parameters . Now SPPT changes this to

with    being a random value changing with time and space but not in the vertical (but you could define some tapering). The idea to constrain    is such that

  • the sign up the tendencies is never reversed

  • the tendencies are at most 2x larger after perturbation

So the stochasticity is multiplicative, in regions/times when the parameterizations are small, so is the perturbation, but with larger tendencies form parameterizations the perturbation is also stronger; satisfying the conceptual idea of uncertainty from the parameterizations scaling with the size of those.

You can use SPPT as follows. Start by defining a random_process, this controls how the random values are created (see Random processes)

Implementing your stochastic parameterizations with their own random processes ​

If you want to implement a new stochastic parameterization with an independent noise realization, you can just make a random process one of the fields of your parameterization. In this case however, you have to manually update/draw new numbers with update_random! within your parameterization, e.g. in its parameterization!(vars, ...) method that is called once per time step before the column parameterizations. A minimal example that heats or cools the surface layer randomly (see Define your own parameterizations for the general interface)

julia
using SpeedyWeather

struct StochasticHeating{NF, RP} <: SpeedyWeather.AbstractStochasticPhysics
    amplitude::NF           # heating amplitude [K/s]
    random_process::RP      # its own random process
end

StochasticHeating(SG::SpectralGrid; amplitude = 1.0e-4) =
    StochasticHeating(SG.NF(amplitude), GridWhiteNoiseProcess(SG))

# its own pattern to draw into, separate from the `random_pattern` of `model.random_process`
SpeedyWeather.variables(::StochasticHeating) =
    (ParameterizationVariable(:heating_noise, SpeedyWeather.Grid2D(), desc = "Random heating pattern", units = "1"),)

# initialize (and seed) the random process with the parameterization
SpeedyWeather.initialize!(heating::StochasticHeating, model::PrimitiveEquation) =
    SpeedyWeather.initialize!(heating.random_process, model)

# draw new random numbers once per time step
SpeedyWeather.parameterization!(vars::Variables, heating::StochasticHeating, model::PrimitiveEquation) =
    SpeedyWeather.update_random!(vars.parameterizations.heating_noise, heating.random_process)

# then use them in every column
Base.@propagate_inbounds function SpeedyWeather.parameterization!(ij, vars::Variables, heating::StochasticHeating, model)
    surface = size(vars.tendencies.grid.temperature, 2)
    vars.tendencies.grid.temperature[ij, surface] += heating.amplitude * vars.parameterizations.heating_noise[ij]
end

spectral_grid = SpectralGrid(truncation = 32, nlayers = 8)
stochastic_physics = StochasticHeating(spectral_grid)
model = PrimitiveWetModel(spectral_grid; stochastic_physics)
simulation = initialize!(model)
run!(simulation, period = Day(1))
